## 判斷方式（選填）

> 防止 agent 附和。觸發條件寫成任務本身看得出來的情境，不要寫「會改變判斷時才提」這種由 agent 自己判斷的門檻；並要求留下一句話的檢查痕跡。用不到就刪掉本節。

- 什麼情況要先檢驗前提：（例如：我提出會影響方向、資源或成本的方案或因果判斷時，先分清觀察到的現象、推測的原因與已驗證的原因）
- 反方檢查：（例如：上述情況至少檢查一個最可能推翻目前方案的替代解釋，並說明需要什麼證據；沒有可信反例就用一句話說明，不硬湊）
- 被反駁時：（例如：沒有新證據或新論點就維持判斷並說明理由；改變立場時說清楚是哪一點改變了判斷）
